# Geographic Search Scope

Приоритет географии не является доказательством. `search_scope.mode`:

- AUTO — пользователь не ограничил включённые территории; сервер упорядочивает
  текущих кандидатов по проверкам и рейтингу. Он не создаёт вымышленные города.
- PREFERRED — сначала кандидаты внутри исходной территории, затем сохранённые
  альтернативы при обоснованном расширении. Рейтинг не становится вероятностью.
- STRICT — сервер запрещает кандидатов и пространственные запросы, выходящие за
  достоверные границы. Ни противоречия, ни user_authorized не разрешают расширение.

## Представление

Необязательный `search_scope` в geo_case_create:

```json
{
  "mode": "STRICT",
  "areas": [{"kind": "CIRCLE", "center": {"latitude": 55.75, "longitude": 37.6}, "radius_m": 20000}],
  "excluded_areas": [],
  "budget": {"max_tool_calls": 200, "max_provider_requests": 30,
    "max_external_requests": 60, "max_duration_seconds": 3600,
    "max_candidates": 500, "max_expansion_levels": 3,
    "preferred_scope_budget_fraction": 0.6}
}
```

Включений/исключений до 10 каждого. COUNTRY, REGION, CITY, DISTRICT разрешаются через
реестр по object_id или name+parent_id. POLYGON задаётся GeoJSON Polygon/MultiPolygon,
включая отверстия; CIRCLE — точка и радиус WGS84. GeoJSON: longitude/latitude.

Административный реестр подключается оператором через GEO_BOUNDARIES_FILE. Файл до
8 MiB: объект `areas`, каждый элемент содержит object_id, kind, name, parent_ids,
geometry, source, retrieved_at, license и content_hash канонической geometry.
Hash обнаруживает изменение и не превращает непроверенный источник в достоверный.
Оператор отвечает за происхождение и разрешение границ. Реальные снимки Москвы, Московской
области, России и Владимирской области находятся в data-sources/osm-boundaries; получение
повторяет scripts/fetch_boundaries.py. Источник polygons.openstreetmap.fr, данные OSM/ODbL,
исходные relation ID, дата, SHA-256 и ограничения сохранены. Это не юридическая гарантия
спорных границ. Синтетические fixtures дополнены тестами этих реальных полигонов.
Москва CITY и Московская область REGION не взаимозаменяемы. Неоднозначное имя
возвращает SCOPE_AMBIGUOUS с вариантами ID, а не случайное разрешение.

Без достоверного полигона — BOUNDARY_UNAVAILABLE. STRICT останавливает пространственные
проверки до уточнения границы; bbox не подставляется вместо города. PREFERRED сохраняет
подсказку с явной неопределённостью. Геометрия административного объекта из аргументов
клиента не принимается; для пользовательской формы есть POLYGON.

## Фильтрация и расширение

Shapely выполняет point-in-polygon. Для разрешения OSM-запроса весь его bbox должен
лежать внутри включённой области за вычетом исключений. Это консервативнее проверки
центра. Для окружности используется консервативная геодезическая оболочка bbox.
Поддерживается переход ±180° через разворачивание долготы и копии полигонов.
Полярные шапки выше 89° не поддерживаются и отклоняются; нельзя трактовать это как
исследованную территорию. Лимит клиентской геометрии — 2000 вершин; доверенный реестр
оператора допускает до 200 000 без упрощения. До 50 компонент MultiPolygon.

`geo_case_next` сначала предлагает локальные кандидаты, сохраняя внешние альтернативы.
После контекстных проверок всех локальных кандидатов, при наличии геометрической
операции и внешней альтернативы, он может журналировать NO_VERIFIED_MATCH и расширить
PREFERRED. Это отсутствие подтверждения, не доказательство отсутствия места.
Явное расширение — geo_case_scope_expand. Оно проверяет режим, ссылки на операции,
состояние дела и бюджет. Старые кандидаты остаются NEEDS_REVIEW/DOWNRANKED.
Проверяемые геометрические противоречия как самостоятельный верификатор пока не
реализованы; текст агента не может заменить их.

Смена scope — geo_case_scope_set, владелец + expected_revision + idempotency_key.
Сохраняются кандидаты и журнал; scope_revision увеличивается. Начальная область,
история расширений и охват отражаются в отчёте. Итоговая подтверждённая территория
пока null из-за отсутствия верификатора сцены.

## Бюджет и покрытие

Счётчики в search_usage сохраняются независимо от ревизий дела. Ограничиваются
поисковые изменения, провайдерные запросы, реальные внешние попытки, время с начала
дела, кандидаты и уровни расширения. Резерв PREFERRED ограничивает новые локальные
OSM-запросы после заданной доли tool budget. Экспорт, диагностика и удаление доступны
для завершения работы даже после исчерпания поиска. Идемпотентный повтор сохранённой
операции не расходует новый бюджет. API retry — отдельная внешняя попытка.

`max_tool_calls` учитывает создание, выполненные поисковые операции, планирование,
чтение состояния и экспорт. Чтения и операции завершения доступны после лимита,
но их счётчик продолжает расти; новая поисковая работа блокируется. Служебные MCP
messages и отклонённые до выполнения аргументы не являются поисковой операцией.
Каждая сетевая попытка, включая retry и попытку DNS, атомарно резервирует отдельную
единицу `max_external_requests` до обращения к сети. Cache hit не расходует её.

NO_VERIFIED_MATCH, INSUFFICIENT_EVIDENCE, COVERAGE_INCOMPLETE и PROVIDER_UNAVAILABLE
нужно различать. Успешная ограниченная выборка OSM не означает исчерпывающего покрытия.
Отказ провайдера возвращается отдельной ошибкой и не удаляет/исключает кандидата.
Успешные выборки сохраняются в scope_checked. Несостоявшиеся проверки сохраняются
отдельно в scope_events с bbox, категорией, scope_revision, временем, кодом ошибки
и negative_evidence=false. Они переживают перезапуск и видны в экспорте. Недоступность
даёт PROVIDER_UNAVAILABLE, исчерпание бюджета — COVERAGE_INCOMPLETE; ни одно состояние
не является отрицательным доказательством. Успех другой области не закрывает прежний
пробел покрытия. Недоступность провайдера блокирует автоматическое расширение.

Не измерялась экономия токенов облачной модели. Измеряются вызовы и размеры локальных
ответов; их нельзя выдавать за сокращение стоимости интеллектуального анализа.

## Источники

Overpass включается явно: до 100 км², сторона bbox до 2°, шесть фиксированных категорий,
до 500 объектов, страница 1–100, HTTP timeout/backoff/Retry-After и ограниченный кеш.
Источник/дата/исходные ID/coverage/hash/ODbL-атрибуция сохраняются. Отрицательный кеш
живёт 60 секунд, положительный — сутки. Устаревшие ответы не выдаются как свежие.
Предел кеша относится к объёму записей, SQLite-файл может занимать больше из-за страниц.

Публичный Nominatim не подключён. Нет OSM-тайлов, панорам и Google Maps-зависимости.
Copernicus GLO-30/GLO-90 исследованы как будущий необязательный DSM-источник;
автоматической загрузки DEM и скрытого нулевого рельефа нет.
